# Constraints and preferences (example)

This is a **worked fictional example** — the persona is "Alex in Austin," not a
real person. It shows what a good constraints pack looks like.

To use this repo:

1. Copy this directory to `constraints-and-preferences/` (that copy is
   gitignored — your real constraints never get committed).
2. Rewrite every file with your own facts.
3. The roast skill reads your copy every run, so it does not fall back to
   generic defaults (want a big company, raise money, hire a team, chase scale).

Extra context for evaluations of potential business models, products, or
services. Info for reference when scoring or filtering any idea.

Not intended to limit possibilities, just steer analysis towards sustainable
options which do not need high probability to scale and get big investment.

## Load order

Read all of these, every roast, in this order:

1. This README (spirit)
2. `location.md`
3. `scale.md`
4. `time-and-income.md`
5. `skills.md`
6. `languages.md`
7. `already-tried.md`
8. `gaps.md` (unanswered on purpose; do not invent answers)

## Do not

- Treat this pack as a veto that forbids imagining alternatives
- Invent hours, capital, distribution appetite, or other gap answers
- Fill a gap with a generic “startup” default
- Skip `already-tried.md` and “discover” a corpse as a fresh alternative
