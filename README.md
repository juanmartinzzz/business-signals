# business-signals

Roast a business idea, then look at alternatives that might actually make money.

Two agent skills that run inside your coding assistant (Claude Code, Cursor,
Muse, or anything that loads `SKILL.md` files):

| Skill | What it does |
|---|---|
| [`roast-and-alternatives`](skills/roast-and-alternatives/) | Takes an idea, a file, or a ramble. Searches the web, roasts the idea on market reality, overlays *your* constraints, then offers 2–4 alternative variations that might live — each with a cheap falsifying test. |
| [`potential-winner-ideas`](skills/potential-winner-ideas/) | Promotes a roast alternative (or a brand-new spark) into a dated, research-backed keeper file for later. |

Every run writes a Markdown file plus a sibling `.html` one-pager (generated by
a script, never by hand). See the samples: [roast](roasts/samples/2026-09-13---roast---link-in-bio-automations-rival.md) · [keeper](potential-winner-ideas/samples/2026-09-13---pwi---talent-wave-newsletter.md).

## Setup

**1. Clone and make the skills discoverable.** Canonical files live in
[`skills/`](skills/). If your agent doesn't read that directory natively, point
it at the copies:

- Claude Code / Muse: `.claude/skills/` (symlinks, already in place)
- Cursor: `.cursor/skills/` (symlinks, already in place)

Some agents need skills copied into a global skills folder instead — copy the
`skills/roast-and-alternatives/` and `skills/potential-winner-ideas/`
directories there.

**2. Create your constraints pack.** The roast is only as good as its picture of
you — without it, the agent assumes generic founder defaults (raise money,
hire a team, chase scale).

```bash
cp -r constraints-and-preferences.example constraints-and-preferences
```

Then rewrite every file in `constraints-and-preferences/` with your own facts:
where you live, what scale you want, how much time and income each mode gets,
your skills, your languages, what you've already tried, and what you won't
answer yet (`gaps.md` — the skill must not invent those). The `.example`
directory is a worked fictional persona ("Alex in Austin") showing what good
looks like.

Your copy is gitignored — it describes you and never gets committed. If you
keep richer personal notes elsewhere, just point the agent at them in chat and
it will use them as an extra overlay.

## Usage

Open the repo in your agent and say:

- **Roast:** "now roast this, please" or "let's use our roast skill" — plus the
  idea, file, or ramble. Output lands in `roasts/` as
  `YYYY-MM-DD---roast---<slug>.md` plus a sibling `.html`.
- **Keep:** "make this a PWI", "promote A2", "save as a potential winner" —
  plus the roast file and alternative number, or a new spark. Output lands in
  `potential-winner-ideas/` as `YYYY-MM-DD---pwi---<slug>.md` plus `.html`.

Your outputs are gitignored (they embed your constraints overlay). Cull them
whenever — deleting a `.html` lets you regenerate it from the `.md`.

## Layout

```
skills/                          canonical skill files (SKILL.md + scripts)
constraints-and-preferences.example/
                                 fictional worked example — copy, don't edit
constraints-and-preferences/     yours (gitignored, you create it)
roasts/                          your roasts (gitignored) + samples/
potential-winner-ideas/          your keepers (gitignored) + samples/
docs/                            naming conventions
```
